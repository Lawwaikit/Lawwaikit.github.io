方案 B

写作 / 知识花园

博客变成主角：首页先放最新文章 + 主题索引（tag 云），项目退为底部紧凑列表。适合走「数字花园」路线。

  • 文章按 主题 而非时间组织，便于长期沉淀
  • 项目卡链接到对应复盘文，形成「做→写」闭环
  • 可加 RSS / Newsletter 入口
适合：你更愿意用「写」建立影响力，项目相对少或偏内部。

方案 C · 推荐起步

单页滚动个人站

所有内容收进一个滚动页：顶部 sticky 锚点导航（关于/项目/写作/现在/联系）。最 cohesive、维护最省，天然适合个人站。

  • 保留现有 Clay Cool 视觉，只是从「多页」变「单页分区」
  • 新增 Now 板块，低成本体现「持续更新」
  • 博客页可先留空，将来作为独立长文入口
适合：想快速成型、内容量中等、不愿维护多页跳转的人。最稳的第一步。

方案 D

完整分站（内容饱满）

保留多页结构但填实：首页聚焦 3 点 + 精选；关于页加 Now；项目页改 case-study 带指标；新增 Uses（工具清单） 板块；联系页补全渠道。

  • 信息最全，但维护成本最高（多页同步）
  • 新增板块：Uses（你用什么工具）、Now、可能的 Resume 下载
  • 适合作为「长期目标态」，分阶段落地
适合：内容已较丰富、想做成像样作品集/名片站的人。

我的建议

短期（本周就能做）：走方案 C 单页滚动。它最稳、维护最省，且把「关于 / 项目 / 写作 / Now / 联系」一次讲清，正好补齐你现在「板块都薄、看不出重点」的短板。同时填入真实项目与一句清晰定位，先把「待补充」扫掉。

中期：把项目卡升级为方案 A 的 case-study 结构（问题→做法→结果 + 指标），这是个人站最有说服力的部分。

长期：若内容变多，再演进到方案 D——拆出独立项目页、加 Uses / Resume。博客页现在留空，将来作为长文入口接回方案 B 的写作流。

无论选哪套，第一步都是确定身份定位（我建议用「测试开发 / AI 工具实践」，与技能页统一），并补 2–3 个真实项目。我可以据此重写首页与关于页内容，继续沿用 Clay Cool 样式。

预览页为独立设计稿，未改动站点任何文件。选定方案后，我会改写对应页面内容与结构，并保留现有 Clay Cool（C3）视觉。
