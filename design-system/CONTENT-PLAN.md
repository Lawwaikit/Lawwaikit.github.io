# 个人站内容架构方案（Content Architecture）

> 整理时间：2026-07-13 19:22 (GMT+8)
> 关联设计稿：`design-system/styles/08-content-designs.html`（真实渲染预览）
> 视觉约束：沿用现有 **Clay Cool（C3 青碧 `#2E8B86` + 板岩 `#5C7C84`）** 配色、圆角与字体，仅调整"展示什么 / 怎么组织"。

---

## 一、背景：为什么要做内容改造

你原本的诉求有两点：① 现有内容**不够丰富**；② 内容的**展示不太合理**。上一轮已把视觉统一成 Clay Cool，但内容仍是"模板感"的占位。本次在**不改样式**的前提下，重新规划"网站该放什么、怎么组织"。

在此之前还做了两个准备动作（与本方案无关但影响呈现）：
- 移除了中英切换 / 日夜模式按钮（专注内容）；
- 博客页改为空白占位（保留顶部博客按钮），展示形式后续再定。

---

## 二、现状诊断：现在有什么 / 缺什么

### 当前 5 页内容饱和度
| 页面 | 真实内容 |
|------|----------|
| 首页 | Hero + 3 方向卡 + 2 项目卡 + 2 文章（1 真实 / 1 草稿） |
| 关于 | 简介 + 4 技能 + 3 时间线（**全占位**） |
| 项目 | 3 张卡片（1 真实 / 2 占位） |
| 联系 | 3 渠道（**仅 GitHub 真实**） |
| 博客 | **已清空为空白页** |

### 三个核心短板
1. **内容单薄** —— 除本站与 1 篇介绍文，几乎全是「待补充 / 建设中 / 草稿」。
2. **身份模糊（最关键）** —— Hero 写「产品思维 / AI 工具实践 / 技术写作」，但关于页技能却写「测试开发 / 后端与工具 / AI / 写作」，两者自相矛盾，访客看不出你到底是干嘛的。
3. **展示无重点** —— 首页像模板，每个板块都薄，没有"最强项"锚点。

> 改造的第一步永远是**先定身份定位**。建议统一为「**测试开发 / AI 工具实践**」，与技能页保持一致，并补 2–3 个真实项目。

## 三、四套内容架构方案

> 每套都在预览页里有**真实渲染的首页 mockup**（填入真实感样例文案，非占位）。

### 方案 A · 作品集优先（Portfolio-first）
- **结构**：Hero 之后**立刻放大项目**——2–3 个带「问题 → 做法 → 结果」的 case-study 卡，关于页压缩成侧栏式短简介；博客退为次级入口。
- **要点**：项目用 case-study 而非标签卡；加入 metrics（周期 / 覆盖率 / 产能）让成果可量化；新增 **Now 板块**体现"活人感"。
- **样例文案**：自动化回归平台（2h→15min，漏测↓40%）/ AI 用例生成器（产能×3）/ 日志巡检 Bot（MTTR↓35%）。
- **适合**：项目 / 成果是你最强资产，想让人 5 秒看懂"你干嘛的"。

### 方案 B · 写作 / 知识花园（Writing garden）
- **结构**：**博客变主角**——首页先放最新文章 + 主题索引（tag 云），项目退为底部紧凑列表；走"数字花园"路线。
- **要点**：文章按**主题**而非时间组织，便于长期沉淀；项目卡链接到对应复盘文，形成"做→写"闭环；可加 RSS / Newsletter 入口。
- **样例文案**：最新《用 RAG 给测试用例做检索增强》《pytest 并行跑进 CI 的踩坑》等；主题云：质量保障 / AI 工作流 / 自动化 / CI-CD / 提示词 / 复盘。
- **适合**：更愿意用"写"建立影响力，项目相对少或偏内部。

### 方案 C · 单页滚动个人站（Single-page）★ 推荐起步
- **结构**：**所有内容收进一个滚动页**——顶部 sticky 锚点导航（关于 / 项目 / 写作 / 现在 / 联系）。
- **要点**：保留现有 Clay Cool 视觉，只是从"多页"变"单页分区"；新增 **Now** 板块（低成本体现持续更新）；博客页先留空，将来作独立长文入口。
- **样例文案**：关于（5 年测试/质量，近 1 年把 AI 融进工程流程）/ 4 个项目卡 / 2 篇文章 / Now 在整理可开源提示词模板。
- **适合**：想快速成型、内容量中等、不愿维护多页跳转——**最稳的第一步**。

### 方案 D · 完整分站（Full multi-page）
- **结构**：**保留多页但填实**——首页聚焦 3 点 + 精选；关于页加 Now；项目页改 case-study 带指标；**新增 Uses（工具清单）** 板块；联系页补全渠道。
- **要点**：信息最全，但维护成本最高（多页同步）；新增板块 Now / Uses / 可能的 Resume 下载；适合作为"长期目标态"分阶段落地。
- **样例文案**：聚焦三方向（可落地质量 / AI 工程 / 技术写作）+ 精选 2 项目 + 1 文章 + 多页结构。
- **适合**：内容已较丰富、想做成像样作品集 / 名片站。

## 四、横向对比

| 维度 | A 作品集优先 | B 写作花园 | C 单页滚动 ★ | D 完整分站 |
|------|------|------|------|------|
| 内容重心 | 项目案例 | 文章/主题 | 均衡·单页 | 全而精 |
| 页面数 | 多页（项目为主） | 多页（博客为主） | 1 页 | 5–6 页 |
| 维护成本 | 中 | 中高 | 低 | 高 |
| 新增板块 | Now | 主题索引/RSS | Now | Now / Uses / Resume |
| 最适合 | 成果强 | 爱写 | 快速成型 | 做作品集 |
| 落地风险 | 需真实项目 | 需持续产出 | 最低 | 需较多内容 |

## 五、建议（分阶段）

- **短期（本周就能做）：走方案 C 单页滚动。** 最稳、维护最省，把"关于 / 项目 / 写作 / Now / 联系"一次讲清，正好补齐"板块都薄、看不出重点"的短板；同时填入真实项目 + 一句清晰定位，先扫掉"待补充"。
- **中期：把项目卡升级为方案 A 的 case-study 结构**（问题→做法→结果 + 指标），这是个人站最有说服力的部分。
- **长期：内容变多后再演进到方案 D** —— 拆出独立项目页、加 Uses / Resume。博客页现在留空，将来作为长文入口接回方案 B 的写作流。
- **无论选哪套，第一步都是确定身份定位**（建议"测试开发 / AI 工具实践"），并补 2–3 个真实项目。
